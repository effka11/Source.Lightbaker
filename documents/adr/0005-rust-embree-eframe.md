# Rust, Embree внутри расчёта, окно на eframe

Окно и запекание вызывают один расчёт, а сам расчёт проверяется треугольниками без BSP. Значит, весь путь от площадки до линейного света — одна программа, без второго языка и без шейдера.

Программа на Rust. Крейты совпадают с модулями, так что расчёт физически не может подключить карту. Луч пересекает треугольники через Embree 4, и только внутри расчёта: при сдвиге лампы окно заново считает люксели, своего трассировщика у картинки нет. Обёртку embree4-rs не берём — она остановилась на 0.0 и требует ту же установленную библиотеку, связку держим сами. Окно — eframe (egui поверх wgpu): панели ламп и рисунок уже посчитанного света. Параллельность по приёмникам — rayon. Пак — zip.

C++ рядом с VRAD облегчил бы чужие структуры BSP и ухудшил бы шов: лучи снова оказались бы в комках. Вычислительный шейдер дал бы второй расчёт, который тестом без карты не прогнать. Игровой движок здесь рисует не тот свет, который пишется в файл.
